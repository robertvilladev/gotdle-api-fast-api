# CLAUDE.md: gotdle-api-fast-api (backend)

Gotdle is a daily Game of Thrones guessing game (in the spirit of loldle / narutodle).
This repo is the API: content library, daily challenges and guess checking.
The Vue frontend lives in a sibling repo: `../gotdle-vue3`.

**Read [`ROADMAP.md`](ROADMAP.md) first.** It holds the MVP goal, the design rules,
the testing policy, the decisions and the current phase. The frontend has its own
roadmap with the same phase numbers:
[gotdle-vue3/ROADMAP.md](https://github.com/robertvilladev/gotdle-vue3/blob/main/ROADMAP.md).

## Stack

- Python 3.14, **uv** for deps and running commands
- FastAPI, Uvicorn
- PostgreSQL 17 + SQLAlchemy 2 (async, asyncpg) + Alembic
- pydantic-settings for config (`.env`; `DATABASE_URL` is required)
- ruff (lint + format), mypy (strict), pytest + pytest-asyncio + httpx2
- Docker Compose for local Postgres (+ CloudBeaver DB UI on :8978)

## Commands

```sh
uv sync                                   # install deps (incl. dev tools)
docker compose up -d db                   # just Postgres
uv run alembic upgrade head               # apply migrations
uv run uvicorn main:app --reload          # dev server → http://localhost:8000/docs
uv run alembic revision --autogenerate -m "msg"   # after model changes, run on host
docker compose up --build                 # full stack (db + api + cloudbeaver)

uv run ruff check . && uv run ruff format --check . && uv run mypy .
DATABASE_URL=postgresql+asyncpg://postgres:password@localhost:5432/gotdle_test uv run pytest
```

Run ruff, mypy and pytest before calling work done. DB tests only run when
`DATABASE_URL` ends in `_test`. Create that database once with
`docker compose exec db createdb -U postgres gotdle_test`. CI
(`.github/workflows/ci.yml`) runs the same checks against a Postgres service.

## Layout

```
main.py            app, CORS, router registration
app/core/          settings, security helpers
app/db/            engine, Base, get_db session dependency
app/models/        SQLAlchemy models (tables)
app/schemas/       Pydantic request/response models
app/routers/       route handlers, one file per resource
alembic/versions/  migrations, never edit one that's already merged
```

## Domain rules (don't break these)

- **One content library, many modes.** `characters` is the hub; quotes, scenes etc.
  reference it. A new mode should mostly be new data plus a small amount of logic,
  not new parallel tables for the same things.
- **One answer per mode per UTC day**, stored in `daily_challenges` with a unique key
  on `(mode, date)`. It's created lazily on the first request, with a deterministic
  pick and no recent repeats.
- **Never return today's answer to the client** before the player has solved it or
  given up. Guesses are checked here, and only feedback is returned.
- **Content lives in seed files in git**, loaded by an idempotent import. Don't write
  content to the database by hand.
- **Auth is parked for MVP.** `auth`/`users` routers exist but nothing should depend on them.

## Conventions

- Use async everywhere (`AsyncSession`, `await db.execute(...)`). Inject the session
  with `Depends(get_db)`.
- Keep game logic (answer selection, guess comparison) in plain functions that don't
  know about FastAPI. That way it can be tested without HTTP.
- Change the schema only through Alembic migrations. Review autogenerated ones
  before committing.
- Keep it small. No repository/service layer until a second real caller needs one.

## Testing

TDD for logic that can silently be wrong: daily selection, guess feedback, content
import idempotency/validation, and one contract test per endpoint against a **real
Postgres**, not mocks. No tests for schemas, config or framework wiring. Target a CI
suite under 2 minutes. See the roadmap's "Testing policy".

## Workflow

- Branch off `main`, keep PRs small, and use Conventional Commits (`feat:`, `fix:`,
  `chore:`, `docs:`).
- Never commit `.env`.
